# 恶意攻击溯源系统——统一开发规范（AI执行版）

## A. 这份文档怎么用

每个组员把整个仓库交给自己的 AI，然后说：

> 我负责【模块名】。先阅读根目录 `AGENTS.md` 和 `docs/00_统一开发规范_AI执行版.md`，再阅读公共 Schema/Model，只修改我的模块。禁止私自改变公共字段和 API。完成后运行契约测试并输出交付清单。

## B. 固定流水线

```text
采集/解析
   ↓
NormalizedEvent
   ↓
检测 + ATT&CK
   ↓
Alert
   ↓
攻击事件关联
   ↓
AttackGraph
   ↓
LLM/多 Agent 溯源
   ↓
TraceResult
   ↓
前端
```

## C. 五个公共对象

### 1. NormalizedEvent
所有日志、主机行为、网络流量必须先统一到该格式。

核心字段：
`event_id/task_id/timestamp/source_type/source/host_id/src_ip/dst_ip/user/action/process/network`

### 2. Alert
检测模块统一输出。

核心字段：
`alert_id/event_ids/host_ids/severity/rule_id/mitre/confidence`

### 3. AttackGraph
关联模块统一输出。

固定为：
`nodes + edges`

每条边必须尽量保存：
`evidence_event_ids/evidence_alert_ids`

### 4. TraceResult
Agent/溯源模块统一输出最终攻击链、证据和归因分析。

### 5. TaskStatus
全系统任务状态只允许：
`pending/running/completed/failed`

## D. 资产统一

所有靶场节点以 `config/assets.json` 为准。

固定 ID：
- attacker01
- c2server01
- firewall01
- webserver01
- mailserver01
- switch01
- officepc01
- coreserver01

如果靶场 IP 发生变化，只改 `config/assets.json`，不要在不同模块中各写一份映射。

## E. 字段规则

### 时间
必须带时区：
`2026-09-08T10:23:42+08:00`

### 空值
未知字段使用 JSON `null`，不要写 `"unknown"` 代替空值，除非字段语义本来就是字符串状态。

### 置信度
统一范围 `0.0 ~ 1.0`。

### Schema 版本
当前固定 `schema_version = "1.0"`。

## F. 谁能修改什么

普通成员：
- 可以修改自己的业务模块；
- 可以添加自己的单元测试；
- 可以添加模块内部私有模型。

普通成员不得直接修改：
- `schemas/`
- `common/models.py`
- `common/enums.py`
- `config/assets.json`
- 公共 API
- 前端公共类型

如果接口确实需要调整，先把“原因 + 影响模块 + 兼容方案”发组长。

## G. 完成标准

模块必须满足：

1. 能独立运行；
2. 能读取 Mock 或真实样本；
3. 输出可被公共 Pydantic Model 接受；
4. 输出可被对应 JSON Schema 验证；
5. `pytest -q` 通过；
6. 告诉下游模块如何调用；
7. 不要求下游阅读本模块内部实现。
