# 前端体验走查与修复（2026-09-10）

本文件记录对前端五个页面的实际走查、修复内容与可复核的前后数据。
走查使用真实任务 `task_exploit-chain-20260910T170757Z`（556 事件 / 5 告警 / 555 节点）
与 `task_covert-negative-20260910T183500Z`（0 告警）两类任务，覆盖"有数据"和"空态"。

## 1. 走查方法

`frontend/scripts/ux-walkthrough.cjs` 用 Playwright 在 1440×900 与 390×844 两个视口
逐个打开任务概览、事件流、检测告警、攻击图、溯源结果，截图并输出机器可判定的指标：

- 可见英文文本节点数（用于发现未翻译的界面文案）
- ≥120 字符且含 `{`/`[` 的代码块数量（用于发现把 JSON 直接铺在页面上）
- 元素横向溢出（`scrollWidth > clientWidth`，排除 1px 屏幕阅读器节点）
- 页面级横向滚动
- 控制台 error/warning

## 3. 修复的问题

### 3.1 把内部结构直接当界面

- `attribution` 原来对每个字段 `JSON.stringify` 后写进 `strong`，候选路径显示成一坨
  事件 ID；现在按字段结构化渲染：数据分类、分析方法、是否使用大模型、ATT&CK 数据源、
  候选路径（事件胶囊：时间 + 行为 + 主机）、APT 相似度表格、四个阶段的路径候选、
  存储到外传候选、结论边界、大模型复核发现（文本 + 引用事件）。
- 证据索引原来把 556 个事件 ID 全部铺开；现在默认只列 12 条并可展开。
- 告警里 `中位间隔 19.99994695186615 s` 之类浮点噪声改为两位小数（`20.00 秒`），
  并给出"秒/是/否"等中文单位。

### 3.2 语言与信息层级

- 三个页面都用后端英文 `summary`/`message` 当 hero 主标题，中文界面里最显眼的是一段
  机器生成的英文；现在主标题是中文概述（如"溯源完成：556 个事件，5 条告警，20 条候选路径"），
  原始英文摘要收进"接口返回的分析摘要（原文，未翻译）"折叠区。
- `SECURITY OPERATIONS / TRACE WORKSPACE`、`WORKSPACE`、`SYSTEM`、`LIVE INVESTIGATION`、
  `TRACE COMPLETE`、`Fit View`、`open`、`DATA_CLASSIFICATION` 等界面文案全部中文化。
- 新增 `src/labels.ts` 统一映射：动作、战术、关系、节点类型、检测器、证据字段名、
  规则中文名、ATT&CK 技术中文注释、后端追加的英文说明句、枚举值与区域名。

### 3.3 攻击图可读性

- 默认不再全量渲染：节点超过 150 且存在告警证据时，默认只显示与告警相关的子图，
  并在画布上方写明"正在显示 167 / 555 个节点、443 / 1008 条关系"，一键重置。
- 新增按节点类型筛选（带数量与颜色）与"只看与告警相关的节点"开关。
- 两个上千条目的原生下拉框替换为搜索框（回车定位第一个匹配），并提示匹配数量。
- 关系超过 120 条时禁用"显示全部关系标签"并说明原因。
- 图例移到画布下方并中文化；大段操作说明收进工具栏问号按钮。
- 并行边（同一对节点之间的多条关系）现在按序号分配曲线距离，不再完全重叠；
  这同时消除了 cytoscape 的 `invalid endpoints` 控制台警告。

### 3.4 数值与时间

- 启发式分数统一显示为 `0.60 / 1.00（启发式）`，不再用 `90 / 100` 或百分数，
  避免被读成置信度或攻击概率；说明文字与呈现方式保持一致。
- 时间统一为 `YYYY-MM-DD HH:mm:ss`（本地），`title` 里保留原始带时区 ISO 值。

### 3.5 空态与移动端

- 概览在无告警时显示 `—` 并说明"当前任务没有告警"；攻击链路改为展示溯源结果里的
  攻击阶段（原来是取攻击图数组前 4 个节点拼成"链路"，具有误导性），没有阶段时说明原因。
- 溯源结果 0 阶段时解释原因（未命中规则或未配置官方 ATT&CK 数据）。
- 移动端底部导航保留文字标签，不再退化成无说明的裸图标。

### 3.6 样式与后端提示（后续补充）

- 全局 `table { min-width: 820px }` 收窄到 `.table-panel`/`.table-scroll` 内的表格，
  其余表格按容器自适应；这是本次归因表格被撑宽的直接原因，改后新表格不会再踩。
- 后端启动时打印一行提示：`ATS_EVENTS_FILE` 同时是持久化存储，每接受一批事件会整体重写，
  不要指向原始证据或导入产物。

## 4. 已知保留项

- 主标题之外仍保留英文原文入口，这是为了可追溯性；不删除接口原句。
- ATT&CK 官方技术名与 APT 组织名保持英文规范写法，仅在前面加中文注释。
- 大图默认过滤会隐藏部分节点，属于"默认视图"而非数据裁剪：关系与证据仍完整存在于
  溯源结果和证据索引中，重置筛选即可看到全图。

## 6. 数据可复现性核对

同一份证据目录连续导入两次：

| 产物 | 结果 |
| --- | --- |
| `normalized_events.json` | 两次 SHA-256 完全一致 |
| `alerts.json` | 两次 SHA-256 完全一致 |
| `attack_graph.json` | 仅 `generated_at` 不同，节点/边集合与顺序完全一致 |
| `trace_result.json` | 仅 `generated_at` 不同 |

结论：导入与关联过程是确定性的，唯一随时间变化的是生成时间戳。此前记录过的
exploit-chain 事件数变化（633 → 556）没有再复现；当时证据目录里的 Zeek 合并日志处于
中间状态，当前目录可稳定复现 556 条，未再深究该中间态。
