# 与开源项目的对比与创新点（2026-09-10）

课程要求「通过对比其他开源项目，验证在自研系统的创新性」。本文件给出对比口径、
可核对的本地证据，以及**明确不成立**的说法。

## 1. 比较对象与口径

| 项目 | 定位 | 与本项目的关系 |
| --- | --- | --- |
| Zeek | 网络流量解析与日志生成 | 本项目**复用**其日志格式与离线解析能力（conn/dns/http/irc/icmp），不自建解析器 |
| RITA | 基于 Zeek 的 Beacon/DNS 统计分析 | 参考其时间间隔与分桶评分思路，本项目实现独立的轻量多特征规则；已在同一批公开日志上分别运行 |
| Sigma | 跨平台日志检测规则库 | 本项目实现**受限子集**解释器（显式指定规则文件），不导入全仓 |
| Sysmon / SysmonForLinux | 主机遥测采集 | 本项目的 Windows 主机行为规则消费 Sysmon 事件（含公开数据集与本地靶场） |
| ATT&CK STIX（MITRE CTI） | 技术与组织知识库 | 本项目只读官方 bundle，用于技术命名、战术归属与精确技术 ID 的 Jaccard 相似度 |
| GraphHunter | 实体关系图与时间路径 | 参考事件→实体三元组与时间单调路径；本项目实现轻量证据图，不含 GNN |
| Arkime / Velociraptor / Wazuh / Security Onion | 完整平台（全流量检索、终端调查、SIEM、发行版） | 只做能力层面比较，未做同环境部署对照 |

## 2. 能力对照

| 维度 | 典型开源组合 | 本项目现状（可核对） |
| --- | --- | --- |
| 数据契约 | 各组件自有 schema，通常靠 ECS/OTel 映射 | 单一 `NormalizedEvent`/`Alert`/`AttackGraph`/`TraceResult` 契约，JSON Schema 校验，`pytest` 196 项 |
| 主机日志 | Zeek 不含；靠 Wazuh/Elastic 解析 | Linux auth/syslog、Windows Security/Sysmon → 统一事件，含登录会话与源 IP |
| 主机行为 | Velociraptor/Osquery/Sysmon | 进程创建/文件访问/内存注入候选；Linux 侧另有 bpftrace 内核跟踪点证据 |
| 网络 | Zeek/RITA/Arkime | Zeek 日志解析 + 6 条网络启发式规则（DNS/HTTP/ICMP 隧道、Beacon、大体积外传、IRC 后门利用） |
| 攻击图 | GraphHunter/Arkime 会话图 | 证据保留型候选图，边携带 `evidence_event_ids`；未观测阶段不填充 |
| 溯源结论 | 多为人工/AI 辅助 | 确定性 `TraceResult`：初始入侵实体、C2 实体、横向/提权/访问/外传候选边、APT 精确技术 ID 相似度 |
| 大模型 | 多为通用助手接入 | 两角色（分析师+审核）显式调用，模型**不能**修改阶段、告警、初始入侵与 C2 身份；提示词最小化（不含原始日志、IP、用户名、命令） |
| 靶场验证 | 多数项目不自带 | 8 节点 v2 靶场 + 2 台隔离脆弱靶标，真实漏洞利用链、隐蔽信道正反例、内核跟踪、内存注入均有原始证据 |
| 公开数据 | RITA 自带少量样例 | IoT-23（两份）+ RITA 上游日志 + **APT29 Evals Day 1 企业域数据**（196,081 条） |
| 部署与规模 | 分布式、ClickHouse/ES、Web UI | 单进程本地 FastAPI，无鉴权、无分布式存储；**不适合生产规模** |
| 规则规模 | Sigma 数千条、Suricata 数万条 | 14 条默认规则（6 网络 + 8 主机），明确标注为启发式候选 |

## 3. 本项目的主张

1. **契约优先的多源融合**：主机日志、主机行为、网络、接收侧边界日志使用同一事件
   对象与同一套校验，跨源证据 ID 在告警、图、溯源结果中全程保留；这比把多个现成
   组件用脚本拼接更容易复核（例如 `docs/exploit-chain-verification.md` 中同一
   `run_id` 下的六类来源）。
2. **可证伪的溯源结论**：`TraceResult` 只呈现有证据支持的阶段，缺证据时返回
   `null`/空数组，并在 `limitations` 中列明推断边界；模型只能附加补充意见。
3. **正反例驱动的验证**：隐蔽信道三类通道都有正例与静默反例；主机规则在真实漏洞
   利用链、内核跟踪与 Windows 内存注入上分别验证，并在公开企业数据上评估误报面。

## 4. 不成立的说法（避免夸大）

- 本项目**不是**更快的 Zeek、**不是** Sigma 的替代品，也没有与之等价的规则覆盖。
- 没有做与 RITA/Arkime/Security Onion 的**同环境同数据部署对照**；现有比较是
  能力层面与同一批公开日志上的分别运行，不能得出性能或检出率的普遍优劣结论。
- 没有做 GNN、图数据库、分布式存储与生产级高可用，单进程 API 无鉴权。
- APT 相似度是**行为相似度**，不是归因；真实利用链上未匹配到已知组织（置信度 0.0）。
- 规则评分是启发式分数，不是校准概率。

## 5. 结论

相对开源生态，本项目的贡献在于**多源证据的统一契约与可复核的候选溯源链**，
以及在受控靶场与公开企业数据集上的端到端验证方法，而不是在单项检测能力上超越
成熟开源项目。若继续推进，优先级应是扩充规则面（引入 Sigma 子集与更多企业数据）
与完善部署形态，而不是重构既有契约。
